# 验收层级与优先顺序

每项以实际回执为准。本仓库的初始 CPU 闭环和真实业务交付分开验收。

## 当前层级

| 层级 | 范围 | 验收证据 |
|---|---|---|
| L0 合同与约束 | 版本/分组、身份与权限、响应防回显、模型概率不越权 | `tests/` 离线自动化测试 |
| L1 CPU 执行 | 两个合成案例，决策层/LoRA，同预算比较、停止恢复、影子批准/回滚 | `ldm smoke` 的本地 `smoke-receipt.json`；不是模型质量结论 |
| L2 真实数据准备 | 物理 2020—2026 年成绩覆盖、缺失规则、完整题目连接 | 本地 `ldm readiness`；成绩核验不等于训练集准备完成 |
| L3 目标模型与效果 | 固定 Qwen3.5-9B revision、决策层＋LoRA、真实留出误差 | 尚未验通；按下面 P0 顺序推进 |
| L4 私人住宅实机 | 真实协议/设备、H200 负载、服务身份、人工回退与现场体验 | 尚未接入；模拟回放不构成设备验收 |

## P0：物理案例

1. 保留原仓库已核验的 219 条私密记录和来源，不提交真实标签，不拼接旧版 223 条，不填补缺失。当前 Windows 接收回执在上游 `docs/windows-handoff-20261109.md`；登记时重新核对字节摘要与各年 30/31/30/33/31/32/32 条及 93/92/94/94/94/91/95 分覆盖。
2. 数字化完整题干、原图/图示、参考答案、评分标准和小问关系。逐条对齐；明确未提供的答案/评分标准，2026 年新旧小问粒度分别映射。当前仍缺该完整连接数据，`training_ready=false`。
3. 固定训练/开发年份、整年/整卷划分、题目输入和本地校准规则。2026 年是已审阅的回顾性比较；最终另需未参与调试的新卷或前瞻考试。
4. 核实 DGX Spark 登录、驱动、ARM/GB10 框架、内存与负载；锁定模型/分词器 revision、精度、序列长度、LoRA 参数及资源预算。当前 CPU 锁不充当 GPU 环境验证。
5. 注册真实目标模型配方。先同题参考基线及只训练决策层对照，再决策层＋LoRA 监督适配。每小问 MAE、实际分值加权 MAE、±5/10pp、题型分组和严重错判都需报告；正式使用阈值由使用方确认。
6. 后续单独核对本地奖励与 RLCD 式更新，并与同预算继续监督训练比较。负 MSE 不自动等于 RLCD 或完整概率校准。

上游资料不提供可直接启动的完整新训练集或已验通的 GPU 配方。本仓库不把旧量表精度、合成模型结果或 Jev 连通检查写成新模型效果。

## P0：私人住宅案例

1. 与主人确定一处空间、一种协议和约定任务，登记家庭语义、数据权限、成员/访客范围、允许动作与关键动作限制。
2. 共用本地准备/划分/训练/评测服务，建立真实授权数据及规则基线。模型只输出有限候选与概率；代码决定范围、确认、弃权、发布与回滚。
3. 接入受控协议网关。当前内置网关没有物理设备客户端，所有路径均报告 `physical_commands_sent=0`。门禁/安防另行设计，未经接入验收不得启用。
4. 完成 H200 整机、电力/散热/噪声、框架、资源预留与训练避峰的实测；基础面板和固定场景独立于模型。
5. 对正常、歧义、越权、停机、旧版恢复和人工确认做现场回放，保存设备反馈及主人/伙伴验收。生产发布权不由训练智能体持有。

### 单灯 demo 前的再决策验收

1. **模拟器阶段。** 在同一条屋主请求中，模型先给出建议。若首选是刷新，或目标灯的状态新鲜度未知，程序只读一次指定节点。拿到可信的当前电源、亮度和色温后，保留原请求、候选和家庭规则，再调用同一检查点一次。两个模型首选分别留档。目标不匹配、读数仍未知、读取失败或第二次仍要求刷新时，停在人工核对。
2. **办公室只读阶段。** 现场指认单灯后，用手动切换前后的证据核实设备身份、读数来源和时效。只有能证明读数代表设备当前状态，才进入第二次推理。演示分别覆盖灯已开启、仍然关闭和无法核实三种情况，由人核对最终建议。网关响应时间本身不足以证明设备上报时间。
3. **受控写入阶段。** 办公室只读演示通过后，再对一盏已指认灯取得具体动作确认，核对实物变化、读回和恢复。两次推理都只产生建议。

模拟研究入口为 `scripts/home_refresh_demo.py`，在已有的 Spark 评分环境中运行。传入 `--model`、`--adapter`、`--bundle`、`--row-id` 和仓库外的 `--output`；从仓库根目录运行时将 `src` 加入 `PYTHONPATH`。选用含 `mock-light-101` 的单灯合成开灯请求，记录每次前向输入、输出以及触发读取的原因。结果和现场进度见[住宅训练追踪页](home-training-tracker.html#refresh-loop-results)。
